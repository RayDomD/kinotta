Splitting the Kinotta skill

Every agent that works on a reel reads one instruction file, skill/kinotta/SKILL.md, which is 535 lines long and describes every job the agent can do. We're splitting it into a short "start here" file plus one file per step, so each job reads only its own instructions. No rule gets added, dropped or changed in meaning. The rules only move.

Before: saved copy of SKILL.md (origin/main, 2026-10-27). Plan: docs/plans/2026-10-27-skill-stages.md, approved by the owner on 2026-10-27.

What one job actually needs

The most common job is Auto's first build. The agent works unattended, adding b-roll over the video, fixing misheard words and deciding cuts. Of the 535 lines, it needs the intro, the "Unattended add b-roll" section and the hard rules. That's 91 lines, about one-sixth of the file. The other 444 lines describe jobs that don't apply to it.

The steps a reel goes through

The owner described the process like this. Each step an agent runs gets its own file, which states what the step reads, what it does, what it writes and what the owner checks.

What changes in the code

Kinotta's prompt for the first build currently points the agent at a section inside the big file:

'Kinotta unattended add-b-roll job. Read request.json, then skill/SKILL.md section "Unattended add b-roll" and follow that path.'

server/core/_internal/requests.ts:71

After the split, it points at skill/stages/02-first-build.md and at the short skill/SKILL.md for the hard rules. The engine, templates, scripts and the reel folder layout stay exactly as they are.

Why it's worth doing

Less to read, less to misread. A job reads the rules for its own step instead of five other paths, so a rule meant for footage reels can't get mixed into a first build.
One place per rule. When a rule for one step changes, you edit that step's file. On 2026-10-27 the owner decided the agent may fix misheard words (keeping count and timing). In the split layout, that rule lives only in 02-first-build.md.
You can see where a reel is. The steps are numbered and match how the owner describes the process. Anyone can open the file for a step and see what goes in, what comes out and what gets checked.

How we make sure nothing gets lost

  • Text is moved word for word. A script compares the saved copy with the new files and lists every old line that doesn't appear in exactly one new file. Only the new "start here" wording is allowed to be unmatched.
  • The skill's name and description stay byte-identical, so the same requests still trigger it.
  • The last check is one real Auto build with Claude Code on a fresh project, compared with the 2026-10-27 manual run.

Gotchas

  • Kinotta copies the whole skill folder into each agent job (server/core/_internal/runner.ts:627), so the step files must live inside skill/kinotta/, not elsewhere in the repo.
  • The hard rules stay in the "start here" file because every step needs them. Moving them into a step file would hide them from the other steps.

## Intent

- Problem: About you gates entry and stores a browser profile, but Make sends only video, title and dead-air strength (`web/src/SimpleMode.tsx:11`, `web/src/SimpleMode.tsx:60`, `web/src/SimpleMode.tsx:129`). The timeline renders shot spans inside one pin target, with a playhead and scrubber but no caption editor (`web/src/SimpleTimeline.tsx:14`).
- Why: Simple mode should offer useful optional choices and let the owner correct captions without opening the detailed editor. It is the default unless the browser tab remembers an editor switch (`web/src/SimpleMode.tsx:28`).
- Outcome: A selected/imported video opens an optional treatment picker. Make applies supported settings, with an explicit route for agent-authored additions. Review shows added visuals, captions and footage on one time axis.
- Constraints: Nothing in the picker is required. Preserve the owner's freedom to override defaults. Follow DESIGN.md tokens; preserve detailed Review behavior and the chosen Working page/shot selection (`web/src/review/_internal/MediaEditor.tsx:172`, `web/src/review/_internal/MediaEditor.tsx:529`). No second caption model or operation system.
- Affected implementation, proposed: `web/src/SimpleMode.tsx`, `web/src/SimpleTimeline.tsx`, `web/src/simple.css`; API request types and server start path; caption extraction from `web/src/review/_internal/EditorialLanes.tsx`; wiring in both Review hosts. Exact current entry points are recorded below. New files in Steps are proposals, not existing components.
- Out of scope: New templates, general editor redesign, caption styling controls, automatic-agent infrastructure without a separate owner decision, new thumbnail generation, and changes to alternate selection. This review edits only this plan and the brief's requested completion note; no code, tests, dashboard regeneration, commits, merges or pushes.

## Goal

1. On successful import **or selecting an existing project video**, show eight cards: Let Kinotta decide (default), Explainer, Interview, Tutorial, Product demo, Short, Lecture, Vlog. Selecting a card changes untouched dials; it changes no existing reel or Working state. Product demo serializes as `demo`, not `product-demo`.
2. Offer B-roll light/medium/heavy, Captions off/phrases/word-by-word, Pace calm/normal/fast and optional notes. Explicit dial overrides survive later type changes. Remember the selection, values and override flags in versioned browser storage; invalid/unavailable storage falls back safely. Make is not blocked by unanswered preferences, while existing video/title/busy guards remain (`web/src/SimpleMode.tsx:58`).
   Below the dials, show a live **b-roll plan preview** (owner requirement 2026-10-21, `docs/mockups/2026-10-21-simple-pace-preview.html`): a 0-to-end ruler with an "Added by Kinotta" lane drawing the target cutaways for the current B-roll (coverage ~20/40/60%) and Pace (shot length ~5.5/3/1.4 s), a count line ("25 cutaways · each about 1.4 s · 60% covered"), the first sample frames, and a note that the agent aims for this target and the real result will differ. It updates instantly on every type or dial change. The same coverage and shot-length targets are what Make passes to the agent, so the preview and the request come from one function.
3. Make applies the captions choice to the initial build; Pace and B-roll go to the b-roll agent as coverage and shot-length targets (decision 5), not to dead-air cutting. Type/density/notes reach the chosen authoring workflow and demonstrably affect that workflow before claiming they affect generated output. Question 4 gates release of that promise.
4. Below playback, show Added by Kinotta, Captions and Your video, with a shared ruler/playhead. A phrase click opens words; clicking a word edits text; Enter/blur commits, Escape cancels; word-edge drag or arrow nudges retime. Caption commits append existing operations and change Working. Opening a phrase, seeking and selecting a type do not change Working. Empty lane clicks seek and open the existing required-note pin composer; caption interactions must not create frame pins. Pins save comments, not caption operations (`web/src/SimpleMode.tsx:138`).
5. Remove mandatory About you and its profile-dependent heading/navigation; optional details remain question 3. Preserve new-reel, editor switch, pin navigation, request copying and playback.

### Caption reuse and the actual Simple host

Loaded native versions and adapted newest legacy versions route through `MediaEditor`, not just `Playing` (`web/src/review/_internal/Review.tsx:530`). Its SimpleTimeline call currently receives only time/total/shots/comments/seek/pin (`web/src/review/_internal/MediaEditor.tsx:556`). The fallback `Playing` call has the same limited data and disallows pins before a version exists (`web/src/review/_internal/Review.tsx:491`). Editing only SimpleTimeline or the fallback would miss the normal Working path.

`MediaEditor` already derives an edited plan from nonflagged operations, mapped graphic spans, a media timeline, source-aware words and caption phrases (`web/src/review/_internal/MediaEditor.tsx:69`, `web/src/review/_internal/MediaEditor.tsx:89`, `web/src/review/_internal/MediaEditor.tsx:234`, `web/src/review/_internal/MediaEditor.tsx:256`). However, `editable` explicitly includes `!simple` (`web/src/review/_internal/MediaEditor.tsx:136`). Introduce a separate caption-edit permission requiring newest Working, nonstale edit list, loaded source root and no busy edit. Keep the broader detailed-editor permission unchanged. Do not remove `!simple` globally.

`EditorialLanes` is reusable presentation with callbacks, but includes graphic selection/dragging and requires more than `onWord/onRetime/onPin`: it also requires `onPhrase`, `win`, `words`, `phrases`, `editable`, `nudge`, `canPin` and graphic props (`web/src/review/_internal/EditorialLanes.tsx:11`). Minimal proposed extraction: `web/src/review/_internal/CaptionLane.tsx`, containing phrase expansion, word/phrase inputs, focus restoration, stacking/measurement and word-edge gestures. Leave graphic rendering/snapping in EditorialLanes, which delegates captions to the extracted component. Reuse the same component in SimpleTimeline; do not duplicate markup/gesture handlers. This changes shared source while preserving detailed Review behavior, rather than promising no Review file edits.

Feed that component:

- `words`: `ReturnType<typeof mediaWords>[number][]`, carrying reel `start/end`, text, `placement`, source identity and `sourceStart`; the model maps these from placement/source words (`server/core/_internal/media-model.ts:377`). `version.transcript` or `Shot.words` alone is not an interchangeable input.
- `phrases`: `MediaCaptionPhrase[]` from `captionPhrases(words)` when captions are enabled (`server/core/_internal/media-model.ts:407`, `web/src/review/_internal/MediaEditor.tsx:256`). Keep the same phrase list for rendering and index callbacks.
- `win`: `{ start: 0, length: total }` initially, with a zero-duration guard; share its axis with all three lanes. Preserve minimum expanded word width and overlap rows (`web/src/review/_internal/EditorialLanes.tsx:58`).
- Operations: `onWord` appends `word-text` at sourceStart with placement; `onRetime` appends `word-timing` with absolute source start/end and existing precision (`web/src/review/_internal/MediaEditor.tsx:594`). Do not treat returned times as reel seconds or deltas. `onPhrase` uses the existing source-bound phrase logic, including the last source word's end (`web/src/review/_internal/MediaEditor.tsx:272`). Extract a shared callback helper only if needed to avoid duplicating that mapping.
- Pins: adapt the word into SimpleMode's existing pin composer, retaining placement/sourceTime and seeking to its reel start; use the identity mapping already used by `pinWord` (`web/src/review/_internal/MediaEditor.tsx:213`, `web/src/review/_internal/MediaEditor.tsx:236`). Existing detailed `pinWord` opens the detailed panel, so passing it unchanged is insufficient. Preserve mapped frame pins at the existing Simple call site (`web/src/review/_internal/MediaEditor.tsx:556`).

For frozen legacy/fallback playback, derive read-only lane words from the existing source/reel mapping rather than inventing native placement IDs (`web/src/review/_internal/Review.tsx:135`). Keep caption edits disabled on frozen versions and while transcription is incomplete. Detailed Review must retain phrase retyping, Escape focus, text edits, keyboard nudges and pins; its current gesture bounds and minimum duration are in `web/src/review/_internal/EditorialLanes.tsx:95` and `:129`.

## Risks

- A UI-only settings implementation would falsely promise b-roll generation. The verified start path only transcribes/cuts/builds existing plan content. Acceptance must inspect actual consumers and authored output, not merely submitted JSON.
- Simple's existing `!simple` edit guard prevents direct callback reuse; removing it broadly enables unrelated editor tools. Keep a caption-specific permission and verify detailed Review remains unchanged.
- Source times, reel times and occurrence IDs differ after cuts/reordering. Shared operations must retain placement/sourceStart and avoid applying edits twice to an already adapted Working model. Test repeated sources and reloads.
- Empty initial graphics, missing transcripts and frozen versions are normal. Keep all three lane labels with honest status and disabled controls; guard division by zero.
- Full-reel phrases can be narrower than a usable target. Retain expansion/stacking and test horizontal reachability; do not silently add whole-editor zoom redesign.
- Cut boundaries alone do not establish automatic dead-air provenance. Keep neutral labels or approve a separate metadata addition.
- Mockup snapping/amber indicators and type-specific defaults are proposals, not existing behavior or validated research conclusions. Resolve the explicit questions before copying their promises into UI text.

## Intent

- Problem: the media editor (`web/src/review/_internal/MediaReview.tsx`) swaps out the Review tab for one long page of forms: a full form per placement, a text box per word, a row per graphic, a two-part library. It is messy and too long, and it drifted from the saved 10-05 Review and Edit layout.
- Why: Kinotta is editing software the owner uses directly, with Claude as an optional helper (PRODUCT.md principle 5). The editor has to read like an editor, and both the owner and Claude need to refer to media by the same names.
- Proposed outcome: built to `docs/mockups/2026-10-08-review-media-editor.html` (decisions and cuts) and `docs/mockups/2026-10-08-review-media-editor-screen.html` (the full screen). Editing stays inside Review: the frame, transport and lanes from 10-05, audio tracks under the ruler with Mute/Solo/volume headers, the per-clip settings on the clip and its right-click menu, and a collapsible left rail with Reel (reels, sections, versions) and Media tabs that pushes the editor when open, where Media holds the minimal library.
- Affected: `web/src/review/_internal/Review.tsx`, `MediaReview.tsx` (split into lane, track, rail and library pieces), `EditsPanel.tsx`, `CommentsPanel.tsx`, `web/src/styles.css`, `MediaReview.verify.ts`, `tests/core/render-media-*.test.ts`, `tests/core/render-media-verify.test.ts`, and the review README.
- Constraints: every capability backed by `docs/2026-10-07-audio-multiple-sources-grilling-decisions.md` survives (AM8, AM9, AM10, AM13, AM15, AM18, AM22, AM23, AM24, AM25, AM29, AM30, AM36, AM38). Track Mute affects the render and track Solo is preview only, consistent with AM29. The `data-verify-*` attributes and the A6 harness survive. Network calls stay in `web/src/api/`. The tests are updated in the same change, so every behaviour stays covered. Lane B: `/impeccable critique`, then `audit`, then the flagged verbs, then `polish`.
- Layout rules (owner, 2026-10-08): the editor never scrolls sideways at any window width. Only the timeline pans and zooms. The middle column uses `minmax(0, 1fr)`, the rail sizes between 240 and 300px, the right panel sizes between 260 and 320px, and the transport row wraps instead of widening the page. The rail is collapsed by default, Reel and Media are tabs rather than stacked lists, and Reel comes first. Verified in the mockup at 1024, 1100 and 1272px with the rail open and collapsed.
- Cuts (owner, 2026-10-08): the per-word list with Source start/end, the list of healthy graphics, the pins list and new-pin form, the sections list in the page, the key help and waveform notes, the Earlier/Later buttons, and the In/Out and Horizontal/Vertical % boxes. - Out of scope: recording and free layout (later stages), automatic ducking (AM23), preview-versus-render timing within one frame, silencing a page's own sound in preview, and agent support for tracks (a separate later plan).
- Open questions: none. The Steps define the implementation sequence.

## Conflicts with the 10-07 audio plan

Checked against `2026-10-07-audio-multiple-sources-implementation.md` and its handoff summary. Each conflict needs a decision before the Approach is written.

- C1, track controls need a model change. The model (`server/core/_internal/media-model.ts`) has placement roles `main | insert | audio | gap` and no tracks. Track Mute, Solo and volume (option A) need a track field on placements plus track gain and mute, carried through the shared mix evaluator and the FFmpeg render (10-07 D4: one gain envelope for both), the validation matrix (D1 audit) and the frozen versions. This is new engine work, not UI only. A UI-only alternative would be to make the header buttons apply Mute or Solo to every clip on the track, with no new model field.
- C2, shortcut collisions. The 10-07 plan binds `[` and `]` to trimming a focused placement to the playhead and `S` to split. The mockup uses `[` to toggle the rail and `S` for the Snip tool (inherited from 10-05). The rail needs another key, and S has to mean one thing.
- C3, insert sound has no row. AM22 says the sound of a product insert starts muted but can be turned on. The new layout shows inserts as picture on the Inserts lane, and the audio tracks hold Speech, Voiceover and Music. An insert with sound needs a place on the tracks (for example on Speech, or on its own row).
- C4, controls the mockup does not place. The overload warning with its Go to buttons (AM29, AM38), Retry for picture and speech (AM36, AM30) and Add gap (AM34) all live in the page today. Proposal: overload spans are marked on the tracks with a single warning line above the transport, Retry sits on the affected clip, and "Insert gap" goes on the Footage lane's right-click menu.
- C5, the library merge. The 10-07 A1 slice split the library into the library and "In this project" with Add to library. The merged list references a file on first use. Discovery does not hide project files whose bytes are already in the library under another path, so the merged list could show the same content twice. That needs de-duplication by content.
- C6, tests and verification move. The A1 and A9 browser tests use the old accessible names ("Media placements", "Graphics attachments", the per-placement Solo checkboxes, the word inputs, "In this project"). The A6 `data-verify-*` contract is attached to the old form markup. Both are rewritten with the layout, and each behaviour stays covered.

### Resolved (owner, 2026-10-08, by grilling in ui-preview; the new decisions win over the 10-07 plan)

Tracks (C1, C3)
- Tracks are stored in the reel model with names and belong to the owner. Each track has Mute, Solo and volume, carried through the shared mix evaluator, the FFmpeg render, validation and frozen versions. Track Mute affects the render; track Solo is preview only (AM29). Agent use of tracks through the Kinotta skill is deferred to a separate plan.
- The lock between footage sound and its picture belongs to the clip. Footage sound sits on any track (Speech by default) and moves with its Footage piece on cut, snip and reorder. No track is special: any track can be renamed, reordered, added or hold other clips.
- An insert keeps its own sound inside the insert clip, as in LumaFusion. It has no track row and no track controls. Dragging that sound onto an audio track turns it into an independent audio clip on that track and leaves the insert silent.

Tools and keys (C2)
- The transport has an icon-only toolbar with the label and key in a tooltip: Select, Blade, Snip | Split, Gap, Duplicate | Snap, Pin.
- Default keys: `V` Select, `B` Blade, `S` Snip, `Ctrl+K` split at the playhead, `M` toggles the rail on Media, `[` `]` trim, the arrow keys move. Every key can be rebound in Settings.

Clip settings
- Double-click, or right-click › Clip settings…, opens a Clip tab in the right panel beside Edits and Comments. It holds every setting for the selected clip and shows only the sections that apply: Sound (waveform, level, mute, fades, speech selection), Timing (start, in, out), Picture (Crop/Fit, position, front/back) and Placement (Follow footage / Stay at time). The right-click menu keeps the quick actions: Clip settings…, Mute, Split, Duplicate, Replace…, Remove.

Problems and gaps (C4)

- Retry: on the clip that failed, plus a note on the frame while that span plays.
- Gap: the Gap button in the toolbar.

Library (C5)
- Shows every file, duplicates included. Adding either path reuses the same content. No content matching for files that haven't been imported.

Settings (new scope)

## Goal

Every native media edit happens inside the Review tab, built to `docs/mockups/2026-10-08-review-media-editor-screen.html`. Nothing swaps the tab for a separate page, and nothing scrolls sideways. Audio sits on named tracks you own, each with Mute, Solo and volume, and preview and render produce the same mix. Every clip setting lives in one Clip tab. The library is one list in the rail. Keys, editing defaults, layout and theme live in Settings. Every settled AM capability still works, and the long `MediaReview` page is gone.

## Approach

- **Model first.** The track field is the one change below the UI, and both engines and the frozen versions depend on it. It lands and is proven with decoded-audio parity before any UI is built on it. A model without tracks (every existing reel and frozen version) gets default tracks in memory: footage sound on "Speech", each existing sound placement on its own track. They are written only on the next Save, so frozen versions stay byte-identical.
- **One mix rule.** Track gain multiplies the clip's envelope, and a track Mute silences its clips in both the browser evaluator (`media-audio.ts`, `useMediaPlayback.ts`) and FFmpeg (`media-render.ts`, `skill/kinotta/engine/pieces.py`). Solo stays preview-only. The overload check runs on the final mix.
- **Review becomes the editor.** `Review.tsx` stops swapping in `MediaReview`. Native media gets the 10-05 lanes (`Lanes.tsx`) plus the audio tracks. `MediaReview.tsx` is split by job into rail and library, lanes, tracks, toolbar, Clip tab and Settings. Each piece is a component under `web/src/review/_internal/`. Network calls stay in `web/src/api/`.
- **One key registry.** A single table of actions and their default keys drives the toolbar tooltips, the key handlers and the Settings Keyboard pane. Rebinding is a lookup, and clashes are detected in one place.
- **Settings are stored per viewer** in browser storage, behind try/catch, following `lastTab.ts`. One person uses one machine (PRODUCT.md), so a server store adds nothing. Themes swap the DESIGN.md token set at `:root`, with neutral dark as the default.
- **Tests change in the same step as the behaviour they cover.** The old accessible names and the A6 `data-verify-*` contract move to the new markup, and every behaviour keeps a test.
- **Lane B finish:** `/impeccable critique`, then `audit`, then the flagged verbs, then `polish`.

## Risks

- R1: the track change touches frozen versions and both engines. A preview/render mismatch would be silent. Mitigation: step 1 proves it with decoded output before any UI exists.
- R2: in-memory default tracks could reorder or re-level an old reel. Mitigation: defaults give unity gain and no mute, so the mix of an old reel must be unchanged, and a test checks that.
- R3: Ctrl+K and other keys collide with browser shortcuts. Handlers prevent the default only while the editor has focus. The Keyboard pane warns on clashes, and Reset restores the defaults.
- R4: `render-media-preview.test.ts` (54K) relies on the old names, so the rewrite can lose coverage. Mitigation: each step lists the behaviours it moves, and step 9 checks every AM against a test.
- R5: full theming can tint the area behind the picture against DESIGN.md. Mitigation: themes are token sets checked by `/impeccable audit` for contrast in each theme.
- R6: the machine ran low on memory during the last render-suite run. Run the unit and render suites one after the other, never together.

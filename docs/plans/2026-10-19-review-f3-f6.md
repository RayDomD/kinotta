## Goal

1. Every affected ffmpeg complex-filter invocation receives -filter_complex_threads with RENDER_THREADS.
2. Saved-version playback reuses a previously verified content hash without rereading an unchanged original, including after a server restart; changed or unverified originals still undergo hash validation before serving.
3. The F5 selectors select PictureLayer explicitly, never UpcomingPictureLayer.
4. Revealing a frame pin while ShotSheet is already open selects that pin's alternate and visibly displays its frame and pins, without changing Working. The F1 behavior after Use remains intact.

## Approach

### F3

Add a failing argument regression at the ffmpeg process boundary, exercising composite, media encode, and audio join through their existing entry points. Assert the built complex-filter arguments include the fixed RENDER_THREADS budget. Extend threaded minimally; also cover argument builders in media-render.ts, including its sound-only complex graph, without adding duplicate conflicting options.

### F4

Proposed approach: persist verified hash plus file identity metadata in a disposable project-local cache under footage/.playback/. Record only hashes actually computed from source bytes, with resolved identity, size, mtime, and ctime; validate the metadata before reuse. Retain the in-memory fast path. Use a stored source contentHash for comparison and content-copy lookup only after verification succeeds. A metadata change, replacement, missing cache, invalid cache, or legacy source without a trusted record requires hashing before serving; a mismatch continues to return null. Capture metadata before and after hashing and do not cache a result when the file changed during hashing. Use atomic cache writes and retain project-path containment checks.

This deliberately does not serve optimistically or move verification into the background. An unverified legacy file still pays one full hash; subsequent requests and restarts reuse verification. Populate the cache where the existing hash operation already computes source bytes, keeping changes confined to hash verification and saved playback. Metadata is an invalidation signal, not proof against an adversary able to restore all file identity metadata; this retains the existing size/mtime cache's trust model and strengthens replacement detection with ctime/identity.

### F5

For snip-save.spec.ts, drop-video.spec.ts, new-reel.spec.ts, transcription.spec.ts, render-media-layer.test.ts, and render-media-sync.test.ts, reproduce the ambiguity with a hidden upcoming layer at the selector seam, then scope only the listed picture selectors to [data-verify-unit="PictureLayer"]. Preserve all existing behavioral assertions.

### F6

Before editing, read the relevant alternates design/mockup and compare the running Storyboard/ShotSheet with the documented pin interaction. Add a failing browser regression that reveals a different alternate into an already-open sheet, including a different-shot transition. Assert the alternate control, rendered iframe revision, visible pin, and unchanged Working choice. Then minimally synchronize the reveal state with the sheet's viewed revision, without reviving stale mount-only initialRevision values or altering the F1 reset in Storyboard. Keep existing Use/remount regressions green. If the same-pin repeat case is reachable, include it in the same interaction coverage.
